# Native skill fixture

`skill_add.json` is a Bead response captured from an isolated real core
server at a79f6f8162c8 with a synthetic operator/proposer and generic files.
Only ask number, timestamp and source provenance/command were stabilized.
The additive `turn: 0` is checked against core `7fa0d4c75ff6`.
The carried bytes, metadata, inventory, hashes, full diff, quoted Does lines
and code weight retain the core wire shape. No live yard data is used.

The real native integration in `test_run_asks.py` checks this shape against
the running core and exercises snapshot installation and native settlement.

`group_add.json`, `group_add_exec.json`, `group_set_prompt.json`,
`group_set_preset.json`, `group_set_effort.json`, `group_set_effort_default.json`
and `group_set_model_effort.json` are Bead asks captured from isolated
yardr builds: the aligned build (upstream plus local replays) and plain
upstream write each of them byte for byte alike, but for
`group_set_model_effort.json`, which the aligned build alone writes (upstream
refuses `model=` when the ask is written). They are a herdr add with a prompt
(HTML, quotes, a tab, trailing spaces, a line that reads like a card sentence
and a trailing blank line), an exec add with its command, directory and
worktrees, a set of a prompt over a standing one, a strong preset, an effort
alone, `effort=default` alone, and a model beside an effort. The yard was
made with `settings set default_kind` (no yardmaster). Only the temp root
(`/synthetic`), ask number and timestamp are stabilized. The real integration
(`RealNativeTests.test_real_native_group_add_and_set_apply_once_through_their_gates`)
asks each card in turn, compares the live response to its fixture after the
same rewrite, and approves it through the bridge.

`group_add_prealignment.json`, `group_set_prealignment.json` and
`group_set_no_prompt_prealignment.json` are the earlier local core's shapes
(captured at `fc7375cf5ad4`), kept to prove the bridge refuses them.

`ordinary_option.json`, `ordinary_words.json` and `ordinary_stage.json` are
actual Bead ask shapes checked by the isolated integration on core
`7fa0d4c75ff6`, including its canonical `turn: 0`. Only ask number and timestamp
are stabilized. The stage ask was
generated by a real manual group and flow template; it has the core's bead
framing and stored options, with no invented You decide. The integration
compares each fixture to the actual serialized core response before driving
it through the bridge and verifying the native outcome. All data is synthetic.

The offline `scripts/preview_run_asks.py --decisions` preview drives the bridge
with these synthetic canonical fixtures and fake Telegram. Its reopen sequence
shows both the retired original message (no controls) and the new open-turn
message. This is presentation evidence, not a live Telegram client capture.
An additional public-send key collision shows the old card retired with no
controls while the reopened ask has no new card; its footer directs the
operator to the yard instead of claiming a newer Telegram card exists.
The real integration also defers through RPC, reopens through the asker's next
note, refuses a queued reply to the original message through the production
poll order, and records exactly one answer from the new message.

`source_new.json`, `source_replace.json` and `source_free.json` were captured
from isolated real core `546e3fdd2127`: a new limits source with one command
file, its replacement changing that file and removing an extra textual
copy, and a commands-free HTTPS declaration. Only temp root (`/synthetic`),
ask number and timestamp are stabilized. The replacement fixture was refreshed
and all three rechecked against isolated core `1918cc80cc75`. The replacement's
Does line `no grant of source synthetic stands.` reflects the standing-grant
disclosure introduced in core `8e1debc3567b`: replacement cards name every
standing grant or explicitly state that none stand. The existing real_native_store
integration compares all three complete wire responses before driving them
through real native approval/carry and checking byte-equal declarations and
installed files. It also exercises standing-file drift, decline, cancel,
wrong bindings and replay. The offline `--source` preview uses the real
replacement fixture with fake Telegram and labels its presentation synthetic.

`source_replace.json` includes the no-standing-grants line verified against
landed core `ced24b0e849c`; its captured files and diffs are unchanged.

`pack_directory.json`, `pack_directory_replace.json` and `pack_embedded.json`
were captured from an isolated build of that landed core. They show a new
directory source pack, an upgrade changing a declaration key and command,
keeping a crew grant and removing an obsolete copy, and the embedded
`telegram` source pack. Only ask number, timestamp and temporary root
(`/synthetic`) are stabilized. The directory snapshots include CRLF setup
notes and exact file hashes. The embedded contract carries source files
without a directory snapshot. No live yard or Telegram data is used.
The native integration also upgrades this repository's complete `yardr/`
pack from `7c0ce69`, checks every installed byte after input edits, and
exercises source/copy/grant drift, decline/cancel/replay and embedded carry.
`scripts/preview_run_asks.py --pack` drives the replacement fixture through
the bridge, including its document header, weight, gate and canonical result,
plus an oversized refusal before any send; all captures are synthetic.
